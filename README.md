# Audio Call Client

Клиентское приложение на Python для голосовых звонков в режиме реального времени 
между участниками одной комнаты (на текущий момент поддерживается два участника).

Приложение захватывает звук с микрофона, кодирует его с помощью аудиокодека Opus, 
передаёт аудиоданные на сервер по HTTP и воспроизводит аудио, полученное от 
других участников.

Поддерживается синхронизация времени с сервером, передача аудио небольшими фрагментами 
(chunks), буферизация воспроизведения и мониторинг задержек.

> [!WARNING]
> На данный момент поддерживается обмен аудиоданными только между 
> двумя участниками комнаты.

## 📋 Требования

- Python 3.10+.
- Файл скомпилированной библиотеки Opus.
- Подключенный микрофон и устройство вывода звука (опционально).

## 🛠️ Установка

1. Клонируйте репозиторий
    ```bash
    git clone <URL>
    cd <project-directory>
    ```

2. Создайте виртуальное окружения
    ```bash
    python -m venv .venv
    ```

3. Активируйте виртуальное окружение
    ```bash
    source .venv/bin/activate  # Linux / MacOS
    .venv\Scripts\activate     # Windows
    ```

4. Установите зависимости
    ```bash
    pip install -r requirements.txt
    ```

## ⚙️ Конфигурация

Настройки приложения находятся в файле `config.py`.

Перед запуском в файле `.env` необходимо указать адрес сервера (`SERVER_URL`).

## ▶️ Запуск

Запустите основной файл приложения:

```bash
python src/main.py
```

Можно сразу передать ID комнаты для обмена аудиоданными:

```bash
python main.py <ROOM_ID>
```

Комната — приватное пространство для обмена аудиоданными.

Если ID комнаты не задан, приложение запросит его ввод.

После ввода ID комнаты приложение выполнит следующие действия:

1. Сгенерирует уникальный идентификатор пользователя.
2. Синхронизирует время с сервером.
3. Инициализирует аудиоплеер.
4. Инициализирует аудиорекордер.
5. Начнёт записывать и отправлять аудиофрагменты на сервер.
6. Будет получать аудиоданные других участников комнаты и передавать их в очередь воспроизведения.

Для завершения работы нажмите `Ctrl+C`.

## 🧩 Принцип работы

Приложение использует обмен аудиоданными небольшими фрагментами (chunks).

### 1. Запись аудио

`AudioRecorder` захватывает звук с микрофона и возвращает аудиоданные, 
закодированные с помощью Opus.

Каждый аудиофрагмент сопровождается следующими метаданными:

- Индекс аудиофрагмента.
- Идентификатор отправителя (`user_id`).
- Временная метка (`timestamp`).
- Продолжительность аудио (`duration`).
- Используемый кодек (`codec`).
- Частота дискретизации (`sample_rate`).
- Количество каналов (`channels`).

### 2. Синхронизация времени

Перед началом обмена данными клиент синхронизирует часы с сервером с помощью 
класса `ServerClock`. Это позволяет использовать единый временной ориентир для 
всех участников комнаты и точнее определять время создания и доставки аудиофрагментов.

### 3. Отправка аудио

Клиент отправляет HTTP POST-запрос на сервер. Запрос содержит два multipart-поля:

- `audio` — бинарные данные аудио в формате Opus.
- `metadata` — JSON с информацией об аудиофрагменте и версии протокола.

### 4. Получение аудио

Сервер возвращает один или несколько аудиофрагментов. Каждый фрагмент содержит:

- JSON с метаданными.
- Бинарные аудиоданные.

Клиент разделяет ответ по `CHUNKS_SEP`, а затем отделяет метаданные от аудиоданных 
с помощью `DATA_SEP` (из файла `config.py`).

### 5. Воспроизведение аудио

Перед воспроизведением клиент проверяет совместимость полученных данных:

- Аудиокодек.
- Частоту дискретизации.
- Количество каналов.

Если параметры соответствуют ожидаемым, аудиофрагмент добавляется в очередь аудиоплеера.

### 6. Мониторинг задержек

Во время работы приложения рассчитываются следующие показатели:

| Показатель               | Описание                                                                                       |
|--------------------------|------------------------------------------------------------------------------------------------|
| Ping                     | Время выполнения HTTP-запроса                                                                  |
| Audio delivery latency   | Время с момента создания полученного аудиофрагмента до момента его получения                   |
| Audio queue duration     | Продолжительность всех аудио фрагментов, ожидающих воспроизведения                             |
| End-to-end audio latency | Задержка от момента записи аудио одним клиентом до момента его воспроизведения другим клиентом |

Расчётная задержка воспроизведения учитывает задержку доставки, продолжительность 
очереди, внутреннюю задержку плеера и точность синхронизации времени с сервером.

## 🌐 Сетевой протокол

Для обмена данными используется HTTP POST с `multipart/form-data`.

Структура метаданных:

```json
{
  "format_version": 1,
  "requested_timestamp": 1234567890.0,
  "chunk": {
    "index": 1,
    "user_id": "1a2b3c4d5e6f",
    "timestamp": 1234567890.0,
    "duration": 0.5,
    "codec": "opus",
    "sample_rate": 48000,
    "channels": 1
  }
}
```
